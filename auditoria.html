Vistoria de segurança e LGPD

Confere, de fora e sem login, se o sistema entrega algum dado a quem não entrou; procura CPF, CNPJ, telefone, e-mail e senha nos arquivos públicos do GitHub; e confere se cada módulo apaga os dados do computador ao sair. Procura na conta de arquivos (Cloudinary) qualquer anexo que ainda abra por link, sem login, inclusive os que foram excluídos das fichas, e tranca. Nada é apagado: depois disso o arquivo só abre pelo sistema. Use de vez em quando, como conferência, ou se desconfiar que um link de anexo foi parar onde não devia.

📖 Manual de emergência

Guia para resolver problemas sem depender de ninguém. Leia o item do seu caso. Os comandos SQL rodam no SQL Editor do Supabase (é preciso estar logado lá). Atualizado em 14/10/2026. Imprima e guarde uma cópia: se o sistema inteiro cair, esta tela também não abre.

🚨 Regra de ouro

Antes de qualquer alteração no banco, tire um backup:

SELECT fazer_backup('manual');

Leva 1 segundo e é o que permite desfazer qualquer coisa.

1. O sistema abriu em branco ou sumiram os dados

Não cadastre nada e não salve nada. Quase sempre os dados estão no banco e o problema é só na tela.

Passo 1, confirme se os dados estão lá. Cada registro deve ter um tamanho grande e uma data recente:

SELECT id, length(data::text) AS tamanho,
to_char(updated_at at time zone 'America/Porto_Velho','DD/MM HH24:MI') AS gravado
FROM app_data ORDER BY id;

Se os tamanhos estiverem normais, siga para o passo 2. Se um deles estiver muito pequeno, vá para o item 2 (voltar um backup).

Passo 2, limpe a cópia do computador: clique em Sair e entre de novo. O Sair apaga a cópia guardada no navegador, e o sistema baixa tudo do banco outra vez.

2. Voltar um backup

O banco faz backup sozinho 3 vezes por dia (duas automáticas e uma às 20h) e guarda 90 dias. Entram Compras, Financeiro, Fábrica, Obra, CRM, Cadastros (com os de teste), as senhas e os lembretes. A aba Backups desta Auditoria mostra quando foi o último.

Passo 1, veja os backups do registro que quer voltar (troque obra pelo nome certo):

SELECT id, sistema, origem,
to_char(created_at at time zone 'America/Porto_Velho','DD/MM HH24:MI') AS quando
FROM app_backups WHERE sistema = 'obra'
ORDER BY created_at DESC LIMIT 20;

Passo 2, volte pelo número da coluna id:

SELECT restaurar_backup(123);

Cada backup é de um registro só: para voltar dois, rode duas vezes. Antes de sobrescrever, a restauração guarda o estado atual, então dá para desfazer.

O caderno de acessos (Entradas, Senhas erradas, Quem abriu o quê) não entra no backup e não precisa: ninguém consegue apagar nem alterar o que está nele.

3. Alguém não consegue entrar
  • Errou a senha 5 vezes: aquele usuário fica bloqueado por 15 minutos, em qualquer computador. É só esperar. A aba Senhas erradas mostra as tentativas.
  • Esqueceu a senha: em Gerenciar usuários, defina uma senha nova e marque como temporária. A pessoa troca no primeiro acesso.
  • Perdeu o celular do código do admin: no Cloudflare, apague o segredo ADMIN_TOTP e clique em Implantar. O admin volta a entrar só com a senha. Depois cadastre o código de novo no celular novo.
  • Tela travada ou em branco: peça um Ctrl+Shift+R. Se continuar, veja o item 5.
4. Tirar alguém do sistema agora

Na aba Agora no sistema desta Auditoria, clique em Deslogar. A pessoa cai em poucos segundos. Se a desconfiança for de senha descoberta, troque também a senha dela em Gerenciar usuários.

5. Publiquei uma alteração e o sistema quebrou

Se foi uma tela (portal, Compras, Financeiro, Fábrica, Obra, CRM), cada uma tem o seu repositório no GitHub:

  1. Abra o repositório do módulo que quebrou e clique no arquivo index.html
  2. Clique em History e escolha a última versão que funcionava
  3. Abra o arquivo naquela versão e publique por cima (três pontos → Revert, ou copie e cole)
  4. Espere 2 a 3 minutos e recarregue com Ctrl+Shift+R

Se foi o Worker (todos os módulos param de uma vez): no Cloudflare, abra daluminium-api → Implantações, escolha a versão anterior e mande implantar. Volta em segundos.

6. Parar o sistema para mexer no banco

No Cloudflare, em daluminium-api → Settings → Variables and Secrets, crie a variável MANUTENCAO com um recado (por exemplo, "Voltamos às 14h") e clique em Implantar. Todo mundo vê o recado e ninguém grava nada. Para liberar, apague a variável e implante de novo.

7. Alterei algo e não vejo diferença

Quase sempre é a memória do navegador. Nesta ordem: Ctrl+Shift+R; espere 3 minutos (a publicação demora); se aparecer a barra amarela "Saiu uma versão nova", clique em Atualizar agora.

8. Testar sem risco

O ambiente de teste (daluminium.github.io/teste) é uma cópia do sistema com dados próprios. Para trazer os dados atuais da produção:

SELECT copiar_producao_para_teste();

É só de ida e substitui tudo o que está no teste (antes, guarda uma cópia do teste nos backups). Pergunte antes se alguém está trabalhando lá.

9. Chaves secretas do Cloudflare

Ficam em Cloudflare → daluminium-api → Settings → Variables and Secrets. Nenhuma aparece no código, e nenhuma pode ser lida depois de salva. Depois de mexer em qualquer uma, clique em Implantar.

  • SENHA_PIMENTA: protege a senha de todos. Nunca apague nem troque. Se sumir, ninguém entra com a própria senha: entre com a senha de reserva do admin e defina senha nova para cada pessoa em Gerenciar usuários.
  • CHAVE_COFRE: tranca os dados pessoais do CRM e dos contratos (CPF, telefone, endereço). Nunca apague nem troque. Sem ela esses dados não abrem mais. Existe uma cópia no seu cofre de senhas, onde você guardou quando ela foi criada: se ela sumir do Cloudflare, crie de novo com o mesmo nome e o mesmo valor.
  • TOKEN_SECRET: assina o acesso de quem está logado. Trocar derruba todo mundo, que entra de novo com a própria senha. Não perde nada.
  • ADMIN_ANDER e ADMIN_ARETUSA: senhas de reserva dos administradores. Funcionam mesmo se o resto falhar.
  • ADMIN_TOTP: o código do celular do admin (ver item 3).
  • SUPA_SECRET: a chave do banco. Apagar para o sistema inteiro. Só se troca junto com a chave no Supabase.
  • CLOUDINARY_API_KEY e CLOUDINARY_API_SECRET: a conta dos anexos. Sem elas, os anexos não abrem nem sobem.
10. Como o sistema é organizado
  • Portal: a porta de entrada, onde se faz o login e o cadastro de usuários
  • Módulos: CRM, Obra, Financeiro, Compras e Fábrica, mais os Cadastros de fornecedores e esta Auditoria
  • Teste: cópia completa para experimentar, com a faixa laranja listrada no topo
  • Worker (Cloudflare): o porteiro. Todo pedido passa por ele, que confere o login e o que cada pessoa pode ver
  • Banco (Supabase): guarda tudo, trancado. Só o Worker entra
  • Anexos (Cloudinary): privados, só abrem pelo sistema, com um bilhete que vale 1 minuto
  • Backups: 3 por dia, por 90 dias. Caderno de acessos: 5 anos, sem como apagar
  • Trava do banco: recusa gravar um registro vazio por cima de um que tem dados
Se nada disso resolver

Os dados quase certamente estão a salvo: a trava e os backups existem para isso. Anote o que apareceu na tela, tire foto do erro e não force alterações até entender a causa. Depois chame o Claude com a foto.
