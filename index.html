🚨 Regra de ouro

Antes de qualquer alteração no banco, tire um backup:

SELECT fazer_backup('manual');

Leva 1 segundo e é o que permite desfazer qualquer coisa.

1. O sistema abriu em branco / sumiram os dados

Não cadastre nada e não salve nada. Provavelmente os dados estão intactos no banco e o problema é só de exibição.

Passo 1 — confirme se os dados estão lá:

SELECT id,
jsonb_array_length(COALESCE(data->'urgente','[]'::jsonb)) AS urgentes,
jsonb_array_length(COALESCE(data->'importante','[]'::jsonb)) AS importantes
FROM app_data WHERE id IN ('compras','financeiro');

Se os números vierem cheios, os dados estão salvos — siga para o passo 2. Se vierem zerados, vá para o item 2 (restaurar backup).

Passo 2 — limpe a cópia local do navegador:

  1. Aperte F12 e vá na aba Application
  2. À esquerda, abra Local storage → clique no endereço do site
  3. Clique com o botão direito na chave dalum-data (Compras) ou fin-data (Financeiro) → Delete
  4. Feche o F12 e recarregue com Ctrl+Shift+R

Não apague a chave dalum-sso — é a sua sessão de login.

2. Restaurar um backup

O sistema faz backup sozinho duas vezes por dia e guarda 90 dias.

Passo 1 — veja os backups disponíveis:

SELECT id, sistema, origem,
to_char(created_at at time zone 'America/Porto_Velho','DD/MM HH24:MI') AS quando
FROM app_backups ORDER BY created_at DESC LIMIT 20;

Passo 2 — restaure pelo número da coluna id:

SELECT restaurar_backup(123);

Atenção: cada backup é de um sistema só. Para voltar Compras e Financeiro, restaure os dois separadamente. A restauração tira um backup automático do estado atual antes de sobrescrever, então dá para voltar atrás.

3. Testar sem risco

Existe um ambiente de teste idêntico ao real, com dados próprios. Para deixá-lo com os dados atuais da produção:

SELECT copiar_producao_para_teste();

A cópia é só de ida. Nada que você fizer no teste afeta o sistema real.

4. Alguém não consegue entrar
  • Senha errada 5 vezes — o sistema bloqueia aquele usuário por 15 minutos. É só esperar. Vale em qualquer computador: trocar de navegador não adianta.
  • Esqueceu a senha — em Gerenciar usuários, defina uma senha nova para a pessoa e marque como temporária. Ela troca no primeiro acesso.
  • Login não abre nada / tela travada — peça um Ctrl+Shift+R. Se persistir, veja o item 6.
5. Encerrar a sessão de alguém

Em Sessões ativas aparece quem está usando o sistema e em qual módulo. O sistema dá sinal de vida a cada 5 minutos; quem fica 1 hora sem mexer sai da lista sozinho. Bolinha verde é atividade nos últimos 10 minutos; laranja, mais tempo parado. O botão Deslogar encerra a sessão da pessoa em até 30 segundos.

6. Publiquei uma alteração e o sistema quebrou

Toda alteração do sistema fica registrada no GitHub, e voltar atrás leva 1 minuto:

  1. Abra o repositório do módulo que quebrou
  2. Clique no arquivo index.html (ou o arquivo alterado)
  3. Clique em History
  4. Escolha a versão anterior que funcionava
  5. Abra o arquivo naquela versão, clique nos três pontos → Revert (ou copie o conteúdo e publique por cima)

Depois aguarde 2 a 3 minutos e recarregue com Ctrl+Shift+R — a publicação não é instantânea.

7. Alterei algo e não vejo diferença

Quase sempre é cache. Nesta ordem:

  1. Ctrl+Shift+R na página
  2. Aguarde 3 minutos — a publicação demora um pouco
  3. F12 → aba Network → marque Disable cache → recarregue
8. Como o sistema é organizado
  • Portal — tela de entrada, login e cadastro de usuários
  • Gestão de Compras e Financeiro — os dois módulos
  • Teste — cópia completa para experimentar
  • Banco de dados — guarda tudo; os módulos nunca falam com ele diretamente, sempre por um intermediário
  • Backups — automáticos 2x ao dia, 90 dias de histórico
  • Trava de segurança — o banco recusa gravar dados vazios por cima dos existentes
9. Chaves secretas do Cloudflare

Ficam em Cloudflare → Workers & Pages → daluminium-api → Settings → Variables and Secrets. Nenhuma delas aparece no código nem pode ser lida depois de salva. Cada linha tem um lápis (trocar) e uma lixeira (apagar):

  • SENHA_PIMENTA — protege as senhas de todos os usuários. Nunca apague nem troque. Ela é como a chave de um cofre: sem a chave certa, nenhuma senha guardada confere mais.
  • TOKEN_SECRET — assina os crachás de quem está logado. Trocar derruba todo mundo (cada um entra de novo com a própria senha); não perde nada.
  • ADMIN_ANDER e ADMIN_ARETUSA — senhas de reserva dos administradores. Funcionam mesmo se todo o resto falhar.
  • SUPA_SECRET — a chave do banco. Apagar para o sistema inteiro. Só se troca junto com a chave no Supabase.

Se a SENHA_PIMENTA foi apagada ou trocada (ninguém consegue entrar com a própria senha):

  1. Não há como recuperar o valor antigo — não existe cópia em lugar nenhum, de propósito. Se ela foi apagada, crie uma nova com o mesmo nome (Add → Secret), com um valor aleatório longo.
  2. Entre como admin com a senha de reserva (ADMIN_ANDER) — ela não depende da SENHA_PIMENTA.
  3. Em Gerenciar usuários, clique em Editar em cada pessoa e defina uma senha nova. Passe a senha para ela, que troca no próximo acesso pelo Alterar minha senha.

Trocar de propósito só faz sentido se houver suspeita de que a SENHA_PIMENTA vazou — e aí o procedimento é o mesmo: trocar e redefinir a senha de todos.

Se nada disso resolver

Os dados provavelmente estão a salvo — a trava e os backups existem justamente para isso. Anote o que apareceu na tela, tire print do erro (F12 → aba Console) e não force alterações no sistema até entender a causa.
